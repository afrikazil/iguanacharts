# iguanaChart — переписывание ядра

Форк `afrikazil/iguanacharts` от `iguanaChart/iguanacharts`. Рабочая ветка — `rewrite/core`.
Цель: заменить движок графика на новое ядро без jQuery, с сохранением того, что
в старом коде реально ценно (математика индикаторов, геометрия фигур, торговый слой).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Совместимость публичного API | **не сохраняем.** `$el.iguanaChart()` уходит |
| jQuery и вся обвязка | **убираем.** Pointer Events вместо hammerjs / mousewheel / event.move |
| Язык | TypeScript, strict |
| Сборка нового ядра | Vite library mode (ESM + **UMD** — UMD обязателен, tradernet грузит через RequireJS) |
| Сборка legacy-бандла | `build.mjs` на esbuild + lightningcss. Gulp удалён |
| Тесты | Vitest, `environment: 'node'` — ядро без DOM |
| FSD | в библиотеке **не применяем** (нет продуктовых срезов). В tradernet обёртка живёт в FSD как `widgets/` |
| Рендер | Canvas 2D. Интерфейс рендерера сменный, WebGL2 — позже и только для тиков/heatmap |
| Точность переноса индикаторов | сверяется с оригиналами, запущенными в node (см. ниже) |
| Баги legacy | не воспроизводим; каждое расхождение закреплено отдельным тестом |

Переключение на форк — одна строка в `frontend/package.json`:

```json
"iguanacharts": "git+https://github.com/afrikazil/iguanacharts.git#rewrite/core"
```

**https, не ssh** — иначе CI не соберёт без деплой-ключей. Yarn пинит SHA, поэтому новые
коммиты ветки сами не подтянутся: нужен `yarn up iguanacharts` либо тег/SHA явно.

Быстрый локальный цикл без пушей (yarn 4 `portal:` делает симлинк, `file:` копирует):

```json

```

Проверять на готовой странице `frontend/src/pages/test-iguana-chart/TestIguanaChart.vue`.

## Факты, которые легко забыть

- **`dist/` закоммичен, `prepare`/`prepack` нет.** yarn при установке из git отдаёт ровно то,
  что лежит в `dist/` в коммите. Значит **в каждом итерационном коммите dist нужно обновлять**,
  иначе стенд соберётся без графика.
- **`dist` воспроизводится побайтово из `src`** — проверено (`npm run verify:legacy`).
  `src` действительно источник правды, а не декорация над руками правленным бандлом.
- **Прод уже отдаёт ES6.** В `src/scripts/chart.js:1335` параметр по умолчанию
  (`forceUpdates = false`), и он доехал до закоммиченного `iguanachart.min.js`.
  Защищать ES5 не нужно. Старый uglify-js ES6 не парсит — это и была причина менять минификатор.
- **Торговый слой раздвоен между репозиториями.** В tradernet лежат AMD-модули, зависящие
  от `iguanaChartCore` и лезущие во внутренности `iChart.*` (~135 КБ):
  `public/javascripts/iguanachart/{draworders,drawtrandorders,drawposition,drawtradepanels}.js`.
  Контракт, который нельзя ломать, шире публичного API библиотеки.
- **Второй потребитель — Banker.** `Banker/public/javascripts/iguanachart/iguanachart.min.js`
  положен руками, путь в его require-config свой (`iguanachart/iguanachart.min`, не из
  node_modules). С форком не обновится — отдельная задача.
- **`.nvmrc` = v10.16.0** остался от gulp. Новый билд работает на Node 22, файл пора обновить.
- `dist/i18n/i18n.en.js` в репозитории устарел относительно `src` (старый gulp-таск
  `copy-resources` не запускали). rspack его всё равно игнорирует.

## Архитектура нового ядра

```
input/     события браузера → команды модели
   ↓
model/     данные и трансформации. НЕ ЗНАЕТ про DOM и canvas
   ↓       invalidate(level)
FrameLoop  один rAF на всё, копит максимум уровня за кадр
   ↓       строит render data — плоские типизированные буферы
render/    рисует. НЕ ЗНАЕТ про модель
```

Правила: поток строго односторонний; ядро без DOM; плагины вместо `switch` по типу;
композиция вместо наследования для фигур; никакой реактивности внутри; ноль рантайм-зависимостей.

Три решения, которые определяют всё остальное:

1. **Ось X живёт в пространстве индексов баров, а не времени.** Выходные, праздники и
   ночные разрывы исчезают сами: между баром N и N+1 всегда ровно `barSpacing` пикселей.
2. **Три режима шкалы цен приводятся к общему внутреннему пространству**, в котором
   отображение в пиксели линейное. Поэтому логарифм и проценты не требуют ветвей в рендерере.
3. **Пейны и типы серий — один контракт `SeriesSource`.** Свечи, объём и линия индикатора
   различаются только реализацией; ядро об их природе ничего не знает. Добавление типа
   серии не требует правок `chart.ts` — в отличие от старого рендерера, где тип графика
   разбирался через `switch` внутри цикла по барам.

### Темы

Встроены две палитры, унаследованные от тем старой библиотеки (`White` и `Dark` в
`jquery.iguana-chart.js`), чтобы график не менял вид при переходе: `LIGHT_COLORS` и
`DARK_COLORS`, обе в `THEMES`. `setTheme('light' | 'dark')` и
`applyOptions({ colors })` меняют палитру на живом графике — тема в tradernet
переключается без перемонтирования компонента. Геометрия при этом не меняется, поэтому
инвалидация уровня Light.

Цвет линии индикатора, заданный вызывающим явно, тема не перекрывает: у пользователя
может быть настроен красный RSI, и смена темы не должна сбрасывать его выбор.

### Пейны

`layoutPanes` делит высоту по весам, но уважает минимальные высоты: пейн, которому не
хватило доли, фиксируется на минимуме и выходит из распределения, остаток делится заново.
Без этого индикаторный пейн схлопывается в ноль раньше, чем это заметит пользователь.

Индикаторы бывают двух видов по размещению: `addIndicatorPane` кладёт в свой пейн
(осцилляторы), `addIndicatorOverlay` — в главный, поверх цены (средние, BBANDS,
конверты, ценовой канал, SAR). Автоскейл главного пейна объединяет диапазоны всех
своих источников, поэтому наложение не требует отдельной шкалы. `removeSource`
убирает источник и сворачивает опустевший пейн.

Автоскейл считается по пейну: объём всегда от нуля (иначе столбики врут о пропорциях),
осциллятор может иметь фиксированный диапазон. У пейнов с заданными уровнями подписи оси
берутся из уровней, а не из круглых засечек: на высоте порядка 80px круглый шаг для
диапазона 0..100 вырождается в одну подпись, а читают там 30 и 70.

Догрузка истории (`prependHistory`) сдвигает индексы, поэтому значения индикаторов
пересчитываются целиком — сшивать состояние здесь означало бы тонкие ошибки выравнивания.

### Как проверяется точность переноса индикаторов

Файлы `src/scripts/ta/functions/*` — прямой порт TA-Lib, и в самих расчётах они не
зависят ни от DOM, ни от jQuery. Поэтому `core/test/legacy-ta.ts` загружает их в node
(подставляя заглушки `$.extend` и `MainController`) и сверяет значения численно.
Это надёжнее повторного вывода формул: перенос проверяется против того, что реально
считалось в проде годами, включая особенности реализации.

Оригиналы отдают массив только для баров, где значение определено, — он короче истории
на период разогрева и выровнен по её концу; `compareWithLegacy` учитывает это смещение.

Два семейства индикаторов:

- **Оконные** (`WindowIndicator`) — значение зависит только от последних N баров.
  Снимок состояния не нужен: `updateLast` перезаписывает текущий бар в окне и считает
  заново. Шаг O(N), зато без накопления ошибки и без машинерии откатов.
- **Рекуррентные** (`IncrementalIndicator`) — EMA, Уайлдер, SAR, кумулятивные.
  Состояние необратимо, поэтому перед шагом снимается снимок.

`core/test/update-last.test.ts` прогоняет **все 37** индикаторов через поток тиков и
сравнивает с прогоном, где бары приходили сразу готовыми. Список там полный намеренно:
тик по последнему бару — единственное место, где рекуррентный индикатор может незаметно
разъехаться.

### Найденные баги legacy — их не воспроизводим

Каждый закреплён тестом, который фиксирует расхождение осознанно.

1. **`TA.VAR` делит на `CandleValueIdx`** вместо `TimePeriod`
   (`meanValue1 = periodTotal1 / this.Settings.CandleValueIdx`, то есть на 7 — индекс
   поля CLOSE). Выдаёт отрицательную «дисперсию». Внутренний `TA.INT_VAR` тот же, но с
   правильным делителем, и STDDEV пользуется им — поэтому эталоном взят INT_VAR.
2. **`TA.STDDEV` при `Deviations != 1` возвращает сырую дисперсию.** Цикл написан как
   `for (i = 0; i < outNBElement; i++)`, а `outNBElement` объявлена и никогда не
   присвоена: `0 < undefined` ложно, тело не исполняется. Ни корня, ни умножения.
3. **`APO` и `PPO` — мёртвый код.** Оба файла объявляют `var APO = ...`, не присваивая
   в `TA`, и нигде в проекте не упоминаются. ~240 строк, которые никогда не исполнялись.
   В перенос не взяты: реализовать их означало бы добавить новую функциональность.
4. **`ADX` добивает начало массива нулями** через `outReal.unshift(0)`, поэтому его
   выход длиной со всю историю, а реальные значения начинаются с бара `2*period - 1`.
   Мы отдаём NaN: ноль рисуется как настоящая линия по нулю и вводит в заблуждение.
   То же у `ELDR` для каналов Signal и Smooth (`splice(0,0,0)`).
5. **`eval` внутри цикла по барам** в `ADX` и `ADOSC`: строка с кодом собирается
   функцией `TRUE_RANGE`/`CALCULATE_AD` и исполняется на каждом баре.
6. **`ELDR` считает `Bulls` и `Bears` и никуда их не возвращает** — классических bull
   power и bear power на графике никогда не было. Мёртвый расчёт не переносим, но и
   недостающие каналы не добавляем: это была бы новая функциональность под видом переноса.

Отдельно про затравки, где легко разъехаться незаметно:

- **MACD**: обе EMA обязаны стартовать на одном баре (`slowPeriod - 1`), то есть быстрая
  засевается средним последних `fastPeriod` закрытий именно там, а не тянет рекурсию
  с бара `fastPeriod - 1`. Для этого у `EmaCore` есть `seedDelay`.
- **ADOSC**: обе EMA засеваются *первым значением* AD, а не средним — режим `'first'`.
- **ZLEMA**: legacy игнорирует собственный lookback и отдаёт значения с нулевого бара,
  а также читает `TA.CLOSE` напрямую, минуя `CandleValueIdx`. Перенесено как есть.
- **SAR**: на первом шаге и `prev`, и `new` указывают на второй бар, а начальный `sar`
  берётся с первого.

### Почему инкрементальные индикаторы устроены через снимок состояния

Последний бар меняется много раз в секунду, а рекуррентные индикаторы (EMA, RSI по Уайлдеру)
необратимы — из состояния после бара нельзя вычесть его вклад. Поэтому перед каждым шагом
снимается снимок, и `updateLast` откатывается к нему и шагает заново. Снимок один и тот же
для любого числа `updateLast` подряд, так что тик стоит O(1), а не полный пересчёт истории.

## Что сделано

- Legacy-сборка переведена с gulp на `build.mjs` (Node 22). `dist/iguanachart.js` и
  `.css` воспроизводятся побайтово; `min.css` уменьшился с 132 КБ до 92 КБ (lightningcss
  вместо cssnano); `min.js` 568 КБ против 532 КБ (esbuild вместо uglify, +6.8%).
- Ядро: модель, кадровый цикл, батчевый рендер свечей, оси, кросс-хэйр, ввод, SMA/RSI.
  60 тестов, типы чисто. UMD-бандл 22 КБ (7 КБ gzip) против 532 КБ у legacy.
- Пейны: общий контракт `SeriesSource`, раскладка по весам, объём и пейны индикаторов.
- Темы: светлая и тёмная палитры, смена на живом графике, свои схемы извне.
- **Перенесены все 39 индикаторов legacy** (37 классов; `INT_MACD` и `INT_VAR` — те же,
  что `MACD` и `VAR`). Каждый сверен с оригиналом, запущенным в node.
- Стенд `core/demo` проверен в браузере: 100 000 баров, три пейна, `setData` 14.5 мс
  (включая полный пересчёт RSI по всей истории), смена набора данных 1 тыс. ↔ 1 млн
  без ошибок, поток тиков по последнему бару.

Три дефекта, найденных на стенде и уже исправленных (стоит помнить как класс проблем):
повторный `setData` с меньшим набором данных падал с `RangeError: offset is out of bounds`,
потому что `BarSeries.setData` перевыделял буферы до сброса `count` и копировал старую
длину в новый буфер меньшего размера — сценарий рядовой (смена инструмента на бумагу с
меньшей историей, смена таймфрейма), и исключение внутри обработчика события терялось
молча;
`fitContent()` терялся, если график монтируется в скрытом контейнере с нулевым размером
(частый случай: свёрнутая панель, неактивная вкладка терминала) — теперь запрос
запоминается и применяется на первом реальном ресайзе; подписи оси времени были
зафиксированы в формате «день месяц» и на минутных барах вырождались в столбец
одинаковых значений — теперь формат выбирается по видимому диапазону.
